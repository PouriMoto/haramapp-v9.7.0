# راهنمای وارد کردن اطلاعات

**همهٔ چیزهایی که خودتان تغییر می‌دهید فقط در همین پوشه است.** بقیهٔ پروژه (پوشهٔ `src` و ...) را لازم نیست لمس کنید.

| فایل | چه چیزی را کنترل می‌کند |
|---|---|
| `site.json` | آدرس Apps Script، دامنه، تعداد موارد صفحهٔ اصلی |
| `content.json` | دعاها، نواها، ویدیوها، بنرها (لینک‌ها و عنوان‌ها) |
| `prayers/<id>.md` | متن هر دعا (اختیاری) |
| `causes.json` | کارت‌های همیاری: نام، شماره کارت، شبا |
| `banners/` | تصویر بنرها (اختیاری؛ یا از لینک https استفاده کنید) |

بعد از هر تغییر، `npm run dev` را بزنید و در مرورگر ببینید. اگر چیزی اشتباه باشد، همان‌جا **به فارسی** می‌گوید کجا و چرا.

---

## ۱) `site.json`
```json
{
  "appsScriptUrl": "https://script.google.com/macros/s/XXXX/exec",
  "domain": "",
  "homeLimit": 3
}
```
- `appsScriptUrl`: آدرس Web App که از Apps Script گرفتید (باید به `/exec` ختم شود). **خالی = داده نمایشی** (برای دیدن ظاهر).
- `domain`: **فقط وقتی** DNS دامنه را تنظیم کرده‌اید، مثلاً `"haramapp.ir"`. تا آن موقع خالی بگذارید (سایت روی `github.io/نام-ریپو` بالا می‌آید).
- `homeLimit`: چند دعا/نوا/ویدیو در صفحهٔ اصلی.

## ۲) `content.json`

### دعا
```json
{ "id": "tavassol", "title": "دعای توسل", "audio": "https://file.erfan.ir/…/tavassol.mp3", "categories": ["other"] }
```
- `id`: انگلیسی کوچک، بدون فاصله (یک بار انتخاب کنید و عوض نکنید).
- `audio`: لینک **مستقیم فایل mp3** (نه صفحهٔ پلیر). اختیاری.
- `categories`: یکی از `fatemiyeh`، `muharram`، `ramadan`، `qadr`، `other`.
- متن دعا: فایل `prayers/tavassol.md` (با همان `id`). اگر نباشد فقط صوت نمایش داده می‌شود.

### نوای معنوی
```json
{ "title": "ای صفای قلب زارم", "artist": "نام هنرمند", "src": "https://…/file.mp3", "categories": ["other"] }
```

### ویدیو (آپارات)
```json
{ "title": "صلوات خاصه امام رضا (ع)", "aparat": "ckn3o4e", "featured": true }
```
- `aparat`: شناسهٔ کوتاه ویدیو. در کد embed آپارات، بخش بعد از `videohash/` است. (در `…/videohash/ckn3o4e/vt/frame` همان `ckn3o4e`).
- `featured: true`: ویدیوی معرفی که **بالای صفحهٔ اصلی** می‌آید (فقط یکی).

### بنر
```json
{ "id": "ramadan-1405", "kind": "campaign", "title": "ماه رمضان", "href": "/prayers?cat=ramadan", "endsAt": "2027-03-20" }
```
- `kind`: `campaign` (مراسم/کمپین) یا `ad` (تبلیغ؛ با `sponsor` نام حامی).
- `image`: لینک https تصویر، یا نام فایلی که در `banners/` گذاشته‌اید (نسبت ۳ به ۱، مثل ۱۲۰۰×۴۰۰).
- `href`: لینک https یا مسیر داخلی مثل `/help`. `startsAt` / `endsAt` اختیاری.

### ترتیب
**ترتیب نمایش همان ترتیب فهرست است** (بالاترین = اول). `"pinned": true` یک مورد را همیشه اول می‌آورد.

### دسته‌ها، مناسبت‌ها و ترتیب مناسبتی (نشست ۴)
- `categories`: فهرست `{id, title, order}`؛ هر دعا/نوا/ویدیو می‌تواند چند دسته داشته باشد.
- `occasions`: هر مناسبت `{id, title, text?, category?, hijri?, ranges?, priority?, enabled?}`.
  - `hijri`: `{fromMonth, fromDay, toMonth?, toDay}` (محرم=۱، صفر=۲، … رمضان=۹). `toMonth` خالی = همان ماه شروع. از ماهی به ماه بعد هم می‌شود (فاطمیه: ۵/۱۳ تا ۶/۳).
  - `ranges`: بازهٔ میلادیِ **همان سال** `[{"from":"2026-12-01","to":"2026-12-10"}]`. اگر برای سال جاری range بگذارید، فقط همان‌ها ملاک است و قاعدهٔ قمری آن سال نادیده می‌شود (ویرایش سالانه طبق تقویم رسمی). مناسبت کاملاً سفارشی = فقط `ranges`.
  - `category`: دسته‌ای که در روزهای مناسبت **جلوتر** نمایش داده می‌شود (دعا/نوا/ویدیو؛ pinned همچنان اول) و کارت مناسبت صفحهٔ اصلی به آن می‌رود.
- `hijriOffsetDays`: عدد ‎-۲ تا ۲؛ اگر تقویم رسمی با ام‌القری فرق داشت همهٔ مناسبت‌ها را یک‌جا جابه‌جا می‌کند.
- بنر: به‌جای `href` می‌توانید `"target": {"type": "cause|prayer|occasion|page", "id": "..."}` بدهید (cause=شناسهٔ کارت همیاری، prayer=شناسهٔ دعا، occasion=شناسهٔ مناسبت، page=یکی از home/prayers/music/videos/help/zikr/messages). build آن را به مسیر داخلی تبدیل و وجود مقصد را بررسی می‌کند؛ `target` بر `href` غالب است. در داشبورد از منوی «مقصد داخل اپ» انتخاب می‌شود.
- تصمیم: مناسبت‌ها و دسته‌ها داخل `content.json` هستند (نه فایل جدا) تا داشبورد یک سند واحد را اتمیک منتشر کند.

### سایت جدید برای لینک صوت
فقط سایت‌های داخل `allowedHosts` (بالای `content.json`) پذیرفته می‌شود. اگر از سایت دیگری لینک می‌گیرید، دامنه‌اش را همان‌جا اضافه کنید.

## ۳) `causes.json` (همیاری)
هر کارت یک بلوک است؛ **این فایل تنها مرجع کارت‌هاست** (حذف از فایل = حذف از اپ؛ ردیف‌های شیت نمایش داده نمی‌شوند). فیلدها:
```json
{
  "id": "masjed-x",
  "title": "مسجد و حسینیهٔ ...",
  "description": "خلاصهٔ یک‌خطی (≤۳۰۰ کاراکتر)",
  "intro": "معرفی کامل مسجد/خیریه، حدود ۳۰۰ کلمه (پاراگراف‌ها با خط خالی جدا می‌شوند)",
  "image": "masjed-x.webp",
  "order": 1,
  "enabled": true,
  "bank": { "bankName": "ملی", "ownerName": "نام صاحب حساب", "cardNumber": "6037…", "iban": "IR…" },
  "payLink": "https://…",
  "contact": { "manager": "حاج آقا …", "phone": "0912…", "address": "…" },
  "channels": { "telegram": "@id", "bale": "id", "eitaa": "id", "rubika": "id", "whatsapp": "0912…", "website": "example.ir" },
  "accounts": [],
  "online": false
}
```
- `title` (نام مسجد/حسینیه/خیریه): تنها چیزی است که جستجو روی آن کار می‌کند.
- `image`: لینک https، یا نام فایل داخل `data/causes/` (webp/jpg/png؛ ترجیحاً ۸۰۰×۴۵۰ و زیر ۱۵۰ کیلوبایت). در لیست بندانگشتی و بالای صفحهٔ کارت نمایش داده می‌شود.
- `intro`: بیش از ۳۳۰ کلمه هشدار، بیش از ۵۰۰ کلمه خطاست.
- `contact` و `channels` همه اختیاری‌اند؛ خالی‌ها نمایش داده نمی‌شوند. کانال‌ها را می‌توان با لینک کامل https یا فقط شناسه نوشت (به لینک رسمی تبدیل می‌شود: `t.me/…`، `ble.ir/…`، `eitaa.com/…`، `rubika.ir/…`، `wa.me/98…`).
- `order`: عدد کوچک‌تر بالاتر. `enabled: false`: کارت موقتاً پنهان (بدون حذف).
- شماره کارت ۱۶ رقم، شبا با `IR` (هنگام کپی، `IR` حذف می‌شود). کارت چندحسابه: هر حساب در `accounts` با `id` یکتا و بانک خودش.
- دکمهٔ «افزودن» از اپ حذف شده؛ کارت جدید = یک بلوک تازه با `id` یکتا در همین فایل (از داشبورد وب `/admin` هم می‌شود؛ docs/ADMIN.md).
- `online` را فعلاً `false` نگه دارید (پرداخت آنلاین با درگاه، بعداً).

### لینک پرداخت (`payLink`) — چطور بگیرم؟
ساده‌ترین راه بدون کد: صاحب همان مسجد/خیریه در پنل درگاه پرداختی که با نام خودش دارد (مثلاً زرین‌پال، «لینک پرداخت/زرین‌لینک») یک **لینک پرداخت عمومی** می‌سازد و فقط آدرس آن (`https://…`) را به شما می‌دهد؛ آن را در `payLink` همان کارت بگذارید. در اپ دکمهٔ «پرداخت آنلاین (لینک پرداخت)» ظاهر می‌شود و پول مستقیم به حساب صاحب همان درگاه می‌رود.
- هر مقصد باید درگاه/مرچنت **به نام خودش** داشته باشد (احراز هویت و قرارداد با سرویس‌دهندهٔ پرداخت با خود اوست). نام و مسیر دقیق منوها را از پنل همان سرویس ببینید؛ ممکن است تغییر کنند.
- **مرچنت‌کد/توکن/رمز را هرگز در `data/` یا GitHub نگذارید**؛ فقط «لینک عمومی پرداخت» اینجا می‌آید. مرچنت‌کد فقط برای درگاه کامل (`payment-service`) لازم است و آن‌جا در متغیر محیطی سرویس می‌ماند.

### اشتراک‌گذاری
دکمهٔ «اشتراک‌گذاری» در صفحهٔ هر کارت، پیامی می‌سازد: عنوان، سپس بانک/نام صاحب حساب/شمارهٔ کارت/شبا (برای کارت چندحسابه همهٔ حساب‌های دارای بانک)، و در پایان لینک همان صفحه.

## خطاهای رایج
| پیام | معنی |
|---|---|
| `JSON نامعتبر` | کاما یا گیومه یا آکولاد جاافتاده/اضافه؛ آخرین مورد هر فهرست کاما ندارد |
| `«id» لازم است` | برای هر دعا یک `id` انگلیسی بنویسید |
| `باید لینک https … باشد` | لینک با `https://` شروع نمی‌شود یا سایتش در `allowedHosts` نیست |
| `دستهٔ ناشناخته` | نام دسته غلط است؛ فهرست مجاز در پیام آمده |

## جمله‌های آمادهٔ درد و دل (`data/presets.json`)
```json
{ "presets": [ { "id": "salam", "text": "سلام آقا جان ❤️" } ] }
```
- ۴–۵ جمله، هر کدام یک جملهٔ کامل و صمیمی + ایموجی (سقف ۱۲۰ نویسه، حداکثر ۸ جمله). `id` انگلیسی کوچک/عدد/خط‌تیره.
- کاربر با یک لمس می‌فرستد و **فوراً** منتشر می‌شود؛ متن آزاد همیشه منتظر تأیید مدیر می‌ماند.
- ⚠ متن نهایی سمت سرور است: بعد از هر تغییر، همین فهرست را در `backend/apps-script/Code.gs` (متغیر `PRESETS`) هم یکسان کنید و Apps Script را «New version» دوباره deploy کنید. تست `tests/codegs.test.ts` اگر یکی نباشند قرمز می‌شود.
